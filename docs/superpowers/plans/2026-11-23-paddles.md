# Paddle Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a controller player give up to four back paddles their own actions (game command, spell, item, macro, or a hold-for-layer of extra actions) from a NewbieNudge window, without touching the game's controller interface.

**Architecture:** `Paddles.lua` owns the saved data and turns it into override bindings on NewbieNudge's own binding owner plus invisible secure buttons; a layer paddle is a secure handler button whose wrapped `OnClick` rebinds the layer buttons while held. `PaddlesWindow.lua` is the editor (learn, drag and drop, command list). The old `/nudge pad` CVar writer is removed.

**Tech Stack:** WoW Forever Lua 5.1 addon (interface 16001), secure templates and restricted snippets; offline tests via `python tests/run.py` (LuaJIT through lupa against `tests/wow_stub.lua`).

**Spec:** `docs/superpowers/specs/2026-11-23-newbienudge-paddles-design.md`

## Global Constraints

- Never write a CVar, hook a Blizzard gamepad frame, or run from Blizzard's Settings panel (anti-goal).
- Binding changes only out of combat; in combat `Apply` queues itself for `PLAYER_REGEN_ENABLED`.
- Saved per character in `NewbieNudgeDB.paddles` with the shape in the spec (`enabled`, `[1..4] = { key, action = { kind, value }, layer = { [slotKey] = action } }`).
- `kind` ∈ `command`, `spell` (spell ID), `item` (item ID), `macro` (macro name), `layer` (paddles only).
- Every user-facing string in `Locales/enUS.lua` and `Locales/esES.lua`; `python tools/locales.py check` must pass.
- Frame names: owner `NewbieNudgePaddleOwner`, paddle buttons `NewbieNudgePaddle<n>`, layer handlers `NewbieNudgePaddleLayer<n>`, layer slot buttons `NewbieNudgeLayer<n><slotKey>` (e.g. `NewbieNudgeLayer2PAD1`).
- All checks green before each commit: `python tests/run.py`, `python -m unittest discover -s tests -p "test_*.py"`, `python tools/locales.py check`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A paddle's spell was unlearned or a macro deleted/renamed: the binding is skipped (macro) or harmless (spell), and the window shows the slot as missing, never a Lua error.
2. The learned key already has a game key binding (e.g. F9 bound to something): the paddle wins (priority override); the window names what it replaces.
3. Combat starts while learning or with the window open: learning is cancelled, the window's controls are disabled, nothing is bound until combat ends.
4. Item not in the bags: the button still uses `item:<id>` (does nothing), the slot icon is desaturated.
5. Two paddles learn the same key: the key moves, the old paddle becomes "not set", only one binding exists.

Each is pinned by a test in the owning task (named there).
